# VelaPack (.vlp) 文件格式规范 v1.0

## 1. 概述

`.vlp` 是 VelaPack 项目的容器格式，设计目标：

- 高压缩率与合理速度的平衡
- 流式处理（无需全量加载）
- 强数据完整性校验（CRC32）
- 跨平台（Windows / macOS / Linux）
- 可扩展的元数据存储

## 2. 文件识别

| 项目 | 值 |
|------|-----|
| 扩展名 | `.vlp` |
| MIME 类型 | `application/x-vlp` |
| 魔数 | `56 4C 50 31` ("VLP1") |
| 版本 | 1.0 |

### 文件命名规范

- 扩展名统一为小写 `.vlp`
- 默认输出名：`原文件名.vlp`（压缩）、去掉 `.vlp` 后缀（解压）
- 压缩已压缩文件时建议显式指定输出名，避免歧义

## 3. 整体布局

```
+------------------+
| 文件头 (Header)   |  变长：20 + meta_len 字节
+------------------+
| 数据块 0 (Block)  |  变长
+------------------+
| 数据块 1         |
+------------------+
| ...              |
+------------------+
| 数据块 N-1        |
+------------------+
| 页脚 (Footer)     |  28 字节固定
+------------------+
```

所有多字节整数均为**小端序**（little-endian）。
所有 CRC32 均为 IEEE 802.3（多项式 0xEDB88320），与 zlib 相同。

## 4. 文件头

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4 | magic | "VLP1" (0x56 0x4C 0x50 0x31) |
| 4 | 1 | version_major | 主版本，当前为 1 |
| 5 | 1 | version_minor | 次版本，当前为 0 |
| 6 | 2 | flags | 位 0：1=有元数据，其余保留为 0 |
| 8 | 4 | block_size | 每个数据块的原始字节数（解压内存基准） |
| 12 | 4 | meta_len | 元数据区域长度（字节），无元数据时为 0 |
| 16 | meta_len | metadata | 元数据（见第 5 节） |
| 16+meta_len | 4 | header_crc32 | 前 16+meta_len 字节的 CRC32 |

## 5. 元数据格式

元数据为键值对序列，键和值均为 UTF-8 编码字节串：

```
+-----------+-----------+-----------+-----------+-----+
| u32 count | u16 klen  | key bytes | u32 vlen  | ... |
+-----------+-----------+-----------+-----------+-----+
```

- `count`：键值对数量
- `klen`：键长度（字节，最大 65535）
- `key`：键内容（不含 null 终止符）
- `vlen`：值长度（字节）
- `value`：值内容

常用键约定：

| 键 | 说明 |
|----|------|
| `filename` | 原始文件名 |
| `mtime` | 修改时间（Unix 时间戳） |
| `content_type` | 原始 MIME 类型 |

## 6. 数据块

每个块独立压缩，块间无依赖，支持并行处理。

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4 | magic | "VLPB" (0x56 0x4C 0x50 0x42) |
| 4 | 4 | orig_size | 解压后长度（<= block_size） |
| 8 | 4 | stored_size | 存储长度（压缩后） |
| 12 | 2 | codec | 0=STORE（原样），1=VZ1（LZ77+Huffman） |
| 14 | 2 | reserved | 保留，必须为 0 |
| 16 | 4 | crc32_orig | 原始数据 CRC32 |
| 20 | 4 | crc32_stored | 存储数据 CRC32 |
| 24 | 4 | block_hdr_crc32 | 前 24 字节（含 magic）的 CRC32 |
| 28 | stored_size | payload | 数据负载 |

记录类型判别：块以独立魔数 "VLPB" 起始，页脚以 "VLPE" 起始，二者完全不同，任何数据字段都不会与魔数冲突，无需依赖取值范围约束。

约束：
- `orig_size <= block_size`
- `stored_size <= block_size + 512`（防止恶意膨胀）
- STORE 模式必须满足 `stored_size == orig_size`

## 7. 页脚

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4 | magic | "VLPE" (0x56 0x4C 0x50 0x45) |
| 4 | 8 | orig_total | 所有块原始大小之和 |
| 12 | 8 | comp_total | 所有块存储大小之和 |
| 20 | 4 | block_count | 块总数 |
| 24 | 4 | footer_crc32 | 前 24 字节的 CRC32 |

页脚与块头的区分：解析器每读一个记录先取 4 字节，若为 "VLPE" 则按页脚解析，否则按块头解析。

## 8. 校验和验证顺序

解压器必须按以下顺序验证，任一失败即终止：

1. 文件头 CRC32
2. 每个块的 `block_hdr_crc32`
3. 每个块的 `crc32_stored`
4. 解压后验证 `crc32_orig`
5. 页脚 CRC32
6. 页脚统计值（`orig_total` / `comp_total` / `block_count`）与累计值一致

## 9. 版本兼容性

- 解压器必须拒绝 `version_major` 大于自身支持版本的文件
- `version_minor` 差异不影响解析（向后兼容）
- 未知 `codec` 返回 `VLP_ERR_UNSUPPORTED`

## 10. 资源限制

| 项目 | 限制 |
|------|------|
| `block_size` | 1 .. 64 MiB |
| 元数据区域 | <= 64 MiB |
| 单个键长度 | <= 65535 字节 |

**内存占用**：解压器内存为 `O(block_size)`（每块需分配原始与存储两份缓冲，实际峰值约 `2 × block_size + 64 KiB`），与文件总大小无关。处理不可信来源时，可在应用层将 `block_size` 钳制到更保守的上限（如 16 MiB）以限制单块内存分配。
